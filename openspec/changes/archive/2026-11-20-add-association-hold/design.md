# Design

## Context

月次更新は取得、`resolve`による関連付け判定、`apply_decisions`による正本適用、カテゴリ再評価、確認Issueの提示を一続きで行います。関連付けの判断は`data/osm-decisions.json`に、根拠（候補一覧と`evidenceHash`）、現在の参照、`decided`や`needs_review`などの状態とともに保存します。カテゴリ判断は`data/categories.json`に`osmId`つきで保存し、公開生成は判断の`osmId`が現在の参照と一致するときだけ`gif-poi`識別子を出します。

西神田コスモス館`019fa880-5cd5-7b01-9dd8-2e4787f423aa`は、検索入力の座標と一致する`node/1655927382`に関連付けられています。この要素は2012年に国土数値情報（公共施設データ2006）から取り込まれたもので、名称「西神田児童・家庭支援センター」は区の現行の施設一覧になく、`social_facility=assisted_living`もこの施設種別に合いません。カテゴリ1499はこのタグから規則で導かれた結果です。

## Goals / Non-Goals

**Goals:**

- 実地調査待ちの施設を、根拠の変化に依存しない人の判断として関連付けの対象から外す
- 保留の記録・解除・確認を専用CLIだけで完結させ、理由・編集者・実行時刻を判断記録に残す
- 保留中の施設を、公開recordとしてはUUIDと座標で維持する

**Non-Goals:**

- OSM要素の修正や実地調査そのもの（別作業）
- 昌平童夢館とさくらキッズのカテゴリ判断（保留とは独立したデータ変更）
- 候補なし施設の検索入力からの除去や、施設の自動削除

## Decisions

### 保留は検索入力のフラグではなく、関連付けの判断状態として保存する

保留は`data/osm-decisions.json`のエントリに`status: "hold"`、`reason`、`previous`（解除した参照）、`human`（編集者・実行時刻）として保存します。関連付けの判断は既にこのファイルにあり、人の判断を編集者・時刻つきで残す形式も揃っているためです。検索入力`inputs/facilities.json`にフラグを足す案は、同じ処理段階の状態が二つの正本に分かれ、月次更新のどの経路がどの状態を見るかを曖昧にするため採りません。

### 保留の記録・解除・確認は専用CLIに集約する

保留の操作は`./fac assoc`だけを入口にします。`--hold`は`--osm-id`、`--choice`と排他とし、`--reason`を必須にします。編集者は`--editor`かgitの`user.name`から取ります。解除は`assoc --osm-id`か`assoc --choice none`で行い、保留の一覧は`./fac category review`が理由つきで表示します。`data/osm-decisions.json`を手で編集する経路は設けません。リポジトリのデータ編集を専用CLIで行う方針に合わせ、判断記録の形を人が知らなくても記録・解除・確認が閉じるようにします。

### 保留は関連付けとカテゴリ判断を同時に取り下げる

保留は「接続先が分からない」という判断であり、カテゴリ判断は関連付けの`osmId`に結びついています。誤った要素のタグから導いたカテゴリを残すと、根拠のない分類を公開し続けるため、保留の記録時にカテゴリ判断を取り消します。保留解除後にカテゴリを判断し直せるよう、施設は未決定として扱います。

### 保留は根拠に依存せず、人の確定だけで解除する

`resolve`は保留エントリをそのまま引き継ぎ、根拠の再計算、Jev、競合の解消を行いません。既存の「該当なし」や未解決のJev結果が根拠の変化で再評価されるのとは対照的です。保留の解除は`assoc --osm-id`による人判断の記録だけに限定し、実地調査で確定した接続先がそのまま正本へ適用されます。

### 保留中の施設は公開recordとして残し、参照だけを外す

公開recordからOSM参照、Wikidata参照、`gif-poi`識別子を外し、UUIDと座標、既存の`schema:subjectOf`を残します。施設の同一性を維持し、実地調査後に同じUUIDへ接続先を記録できるようにするためです。公開データは名称を運ばないため、保留中は名称の解決元が一時的に失われます。これは接続先が未確定であることの正しい表現として受け入れます。

### 保留は関連付けとカテゴリの確認Issueから外し、レビューでは保留として示す

`present`は`needs_review`のエントリだけを提示するため保留は自動的に外れますが、カテゴリ確認Issueは未決定の施設を拾うため、保留を明示的に除外します。`category review`は保留を未決定と混ぜず、保留と理由の一覧として出力し、人の見落としを防ぎます。

## Risks / Trade-offs

- [保留中の公開recordは名称の解決元を失う] → UUIDと座標、`schema:subjectOf`を維持し、実地調査後に同じUUIDへ接続先を記録して名称を回復する
- [保留の解除を忘れる] → 判断記録に理由・編集者・時刻を残し、`category review`が保留を理由つきで一覧表示する
- [保留中に付けたカテゴリ判断は接続先の確定で失効する] → 仕様どおり関連付けの変更として再評価される。保留中はカテゴリを確定しない運用にする
- [取り下げた参照の履歴が判断記録から消える] → `previous`に解除したOSM IDを残し、gitの履歴と合わせて追跡できるようにする

## Migration Plan

1. 判断記録の保留エントリ、`assoc --hold`、`resolve`と`present`、カテゴリ再評価と`review`の除外、テストと文書を実装する
2. 西神田コスモス館へ保留を記録し、OSM参照・Wikidata参照とカテゴリ1499を取り下げる
3. `./fac jsonld-validate`、`./fac category review`、テストで検証してコミットする
4. 実地調査とOSM修正の完了後、`./fac assoc <id> --osm-id <id>`で接続先を記録し、カテゴリを判断する
5. ロールバックは、保留記録とパイプライン変更を含むコミットを戻せば参照とカテゴリが復元される
