# Tasks

## 1. 検索入力と判断記録

- [ ] 1.1 出典別の検索入力を`inputs/facilities.json`へ統合し、スキーマと読み込み処理を更新する。移行前後のUUID・検索対象・有効な座標が一致し、重複UUID・情報不足を拒否し、公開除外指定を維持するテストで確認する。
- [ ] 1.2 `data/osm-decisions.json`の読み書きと根拠の正規化を実装する。候補順・取得日時でハッシュが変わらず、判定に使う名称・座標・QID・タグの変更では変わるテストを追加する。
- [ ] 1.3 検索入力と判断記録の人が編集する項目を`docs/reference/data-contracts.md`へ記載する。入力例を実際の検証コマンドへ通して確認する。

## 2. 照合順序とJev

- [ ] 2.1 同じ根拠に対する人の確定、既存の型付きOSM ID、一意なQID、Jevの順に照合する。型違い、QID矛盾、50m境界、人の「該当なし」の優先、名称・近接座標だけでは確定しないことをテストする。
- [ ] 2.2 過去の名称・近接座標だけの確定結果を再評価する移行処理を実装する。既存参照の継続で再評価を迂回しないことを、取得済みデータから作る事例で確認する。
- [ ] 2.3 TypeSafe System Oneの`choice`接続を実装し、`jev-1.14.0`、`TYPESAFE_API_KEY`、初期閾値0.90を設定する。固定API応答で候補選択・「該当なし」・閾値境界・不正応答・通信失敗・入力上限をテストし、一施設につき三者投票が発生しないことを確認する。
- [ ] 2.4 Jevの使用量・信頼度・確率を判断記録へ保存する。日本語名称、既知の誤一致、同名施設、同一建物内の別施設、正解候補なしの評価事例を追加し、期待する選択と人手確認への振り分けを確認する。
- [ ] 2.5 `docs/how-to/update-osm.md`と`docs/reference/verification.md`に照合条件、閾値、評価方法、実費の確認方法を記載する。文書の設定名と検証手順が実装と一致することを確認する。

## 3. 確定分の反映と参照解除

- [ ] 3.1 正本への反映を施設単位にし、判断待ちの施設を保ったまま確定分を反映する。二施設の一方だけが判断待ちになる事例と、同じOSM IDの重複割り当てを拒否する事例で確認する。
- [ ] 3.2 OSM参照の置換と明示的な解除を実装する。古いWikidata参照の除去、UUIDと有効な座標の維持、候補なしと人の不採用の区別をテストする。
- [ ] 3.3 取得・検証・Jev接続の失敗で、その実行のデータ変更を公開しないようにする。失敗を低信頼度としてIssue化せず、正本が変わらないことを失敗注入テストで確認する。
- [ ] 3.4 `docs/reference/data-contracts.md`に関連参照の置換・解除と判断待ちの扱いを記載する。判断記録が公開JSON-LDとPages配布物に含まれないことを検証する。

## 4. Issueでの確認・修正

- [ ] 4.1 施設ごとの確認Issueの作成・再利用・更新を実装する。対象、現在の参照、候補、距離、リンク、理由、Jevの結果、選択肢と確定欄が表示され、GitHub上の発言に`[bot]`が付くことを固定出力で確認する。
- [ ] 4.2 チェック途中を反映せず、一つの選択と確定欄だけを受け付ける。未選択、複数選択、候補改変、コメントだけの回答、権限不足を拒否し、形式不正時に修正方法を示すテストを追加する。
- [ ] 4.3 Issue回答と保存済み根拠を照合する。古い回答の拒否、根拠変更時の欄のリセット、根拠不変時の途中選択の維持、人の確定後の再通知抑止、artifact期限切れ後の回答をテストする。
- [ ] 4.4 最新の正本に回答を適用し、公開成功後にIssueを閉じる。重複イベント、月次取得との競合、反映後の公開失敗と再実行で二重適用や早すぎる完了が起きないことを確認する。
- [ ] 4.5 `docs/how-to/review-osm-candidates.md`をIssueの操作手順へ置き換える。候補選択、「該当なし」、確定、不正回答の修正、根拠更新後の選び直しを実際の本文例で確認する。

## 5. Actionsの月次更新と自動公開

- [ ] 5.1 `update-osm.yml`を月次`17 3 1 * *`、手動再実行、Issue本文編集で起動する。取得と回答反映を分岐し、確定済み未反映Issueの再読み込みと編集者の権限確認を実装する。複数Issueの編集と待機実行の置き換えで回答を失わないことをテストする。

- [ ] 5.3 `publish-pages.yml`を明示的に再利用し、反映コミットSHAを渡して公開する。自動コミット後に公開が開始され、古い実行が新しいmainの公開を上書きせず、公開失敗を成功扱いしないことを確認する。
- [ ] 5.4 workflowのCLI呼び出しを実装済みの単一経路へ統一する。未対応引数を除去し、workflowと同じ引数で取得済みfixtureから検証・ビルドまで実行できることを確認する。
