# Issueでの確認・修正

通知された`[bot] OSM確認: …`というIssueを開きます。本文には対象UUID、現在の参照、確認理由、Jevの結果、候補の名称・OSM ID・距離・地図へのリンクがあります。リポジトリへのwrite権限以上を持つ人が本文を編集してください。

1. 候補のリンクを確認し、一致する候補を一つ選びます。一致しなければ`none`の「該当なし」を選びます。
2. 最後の「判断を確定する」をチェックします。
3. Actionsの`Update OpenStreetMap data`で回答反映と公開の成功を確認します。公開が成功するとIssueが閉じます。

選択部分の例です。

```markdown
- [x] `node/123` 対象施設 / 12.0 m / OSM・地図へのリンク
- [ ] `none` 該当なし（OSMとそれに伴うWikidataの参照を解除）

- [x] 判断を確定する
```

候補だけのチェックは途中の選択として残ります。コメントでの回答は反映しません。「該当なし」で確定するとOSMとそれに伴うWikidataの参照を外し、施設UUIDと有効な座標を残します。

複数選択、未選択、保存済み候補にないID、対象施設IDの不一致、権限不足は反映せず、botが修正方法をコメントします。確定欄を外して本文を正しい状態へ戻し、一つ選んで確定し直してください。説明文やJevの信頼度の編集だけでは回答を拒否しません。

取得し直して根拠が変わると、同じIssueの本文とチェック欄が更新されます。新しい候補で選び直してください。根拠が同じなら途中のチェックを保ち、手動で閉じたIssueも開き直しません。採用済みの接続は取得結果に残る間維持します。人の「該当なし」は根拠が同じ間維持し、根拠が変われば再判定します。

公開失敗時はIssueを開いたまま残します。Actionsを再実行してください。回答処理は保存済み候補への反映・Git保存・公開・クローズだけを行い、取得・Jev判定・未解決Issueの再提示は行いません。Actions artifactの保存期限には依存しません。

`[bot] OSM接続先なし`は、接続先が見つからなかった対象をまとめた通常の通知です。回答用のチェック欄はありません。実在を確認し、検索入力の除去またはOSMへの収録を検討してください。施設と検索入力の削除は自動では行いません。
